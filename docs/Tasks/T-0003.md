# T-0003: SIGTERM exits within 5 s even mid-cycle

**Status:** [DONE] | **Branch:** `task-T-0003-sigterm-exit` | **Created:** 2026-10-16 | **Parent:** [P-0001](../Projects/P-0001.md)

## Why

`tests/test_app_process.py::test_token_never_logged_at_debug` fails on clean `dev` with `TimeoutExpired` at `terminate(5)` (see MEMORY `test-app-process-sigterm-flaky`). The Latarnia Service App contract requires a clean exit 0 on SIGTERM (cap-001 `sigterm_clean_exit`); on the Pi systemd would wait for its stop timeout and then SIGKILL.

## Root cause

uvicorn finishes its graceful shutdown immediately (the scheduler cancels the sync and watch tasks), but the process then lingers. The DNS and TLS checks run through `asyncio.to_thread` in default-executor threads, and a cancelled `await` does not stop the thread. `asyncio.run` (inside `uvicorn.run`) joins the executor on close, and interpreter exit joins it again, so the process waits for every in-flight check to hit its socket timeout (DNS 5 s, TLS connect 10 s; the dev default watches `home.stanham.com:8443`, which times out). `test_starts_with_cli_args_and_clean_sigterm` passes only because SIGTERM arrives before any check is in flight.

## Scope

- [x] `app.py` `main()`: run `uvicorn.Server.serve()` on a plain event loop (no `asyncio.run`), and after the graceful shutdown flush logging and `os._exit(0)` instead of joining the worker threads.

## Out of scope

- Cancelling the threads, shorter timeouts, or an own thread pool (new abstractions, behaviour change).
- Deploying (separate step).

## Promotion check

One function in one subsystem (app shell), no schema, no new service: stays a Task.
