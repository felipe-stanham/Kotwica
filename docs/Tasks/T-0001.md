# T-0001: tst manages its own Managed Record (home-tst)

**Status:** [DONE] | **Branch:** `task-T-0001-tst-managed-record` | **Created:** 2026-10-15 | **Parent:** [P-0001](../Projects/P-0001.md)

## Why

P-0001 made tst watch-only and did not deploy Kotwica there. The first run on the Pi under the real Latarnia contract would then be prd, which writes `home`, the record Caddy's certificate depends on. With a record per environment (`kotwica-dev`, `home-tst`, `home`), Latarnia tst on the Pi exercises the full write path before `home` is touched.

Operator decision: 2026-10-15 (record renamed from `kotwica-tst` to `home-tst` the same day, because tst becomes a real routed name) (supersedes the spec rows "tst is watch-only" and "Kotwica not deployed to tst").

## Scope

- [x] `kotwica/config.py`: tst default `managed_record` = `home-tst` (was none). Watch-only stays possible with `TST_MANAGED_RECORD=none`. The single-writer guard for `home` is unchanged.
- [x] Tests: tst default, watch-only override, guard in tst, tst writes only `home-tst`, health row 3 watch-only config.
- [x] Docs: P-0001 spec and P-0001.md (criteria, env matrix, constraints), architecture.md, SYSTEM.md, README (tst operator section).
- tst default Watched Host is `home-tst.stanham.com:443` (per-env `watched_hosts` default in `config.py`). `home-tst` is the public name of the tst environment, to be served by Caddy/Latarnia tst on :443 (separate, outside Kotwica). Until then the tst TLS check reports an error, which is expected.
- prd keeps its Watched Hosts unchanged (`home:443`, `home:8443`); dropping `:8443` is a follow-up once tst has moved off it.
