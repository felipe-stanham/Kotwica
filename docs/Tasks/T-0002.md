# T-0002: prd watches home.stanham.com:443 only

**Status:** [DONE] | **Branch:** `task-T-0002-watch-443-only` | **Created:** 2026-10-16 | **Parent:** [P-0001](../Projects/P-0001.md) | **Follows:** [T-0001](T-0001.md)

## Why

Operator decision 2026-10-16: tst moves from `:8443` to `:443` under its own name `home-tst.stanham.com`, so `home.stanham.com:8443` will stop existing. prd Kotwica would then report `error` forever for a host that is gone. Dropping it before the first prd deploy avoids a redeploy later and a false alarm.

## Scope

- [x] `kotwica/config.py`: prod default `watched_hosts` = `home.stanham.com:443` (per-env default mechanism from T-0001). The shared default (used by dev) is unchanged.
- [x] Tests: one new config test (`test_prod_watches_only_443`); three `test_host_watch.py` tests now pass an explicit two-port `PROD_WATCHED_HOSTS` because they exercise several hosts. Docs: README, SYSTEM.md, `P-0001/spec.md` (env table, scope text, new criterion), `P-0001.md` (new criterion), `TESTS.md`.
- It cannot be done through `secrets.env`: Latarnia injects only the secrets declared in the manifest, so a `PROD_WATCHED_HOSTS` line would never reach the app.

## Out of scope

- Moving Caddy/Latarnia tst to :443 (Latarnia work).
- Changing dev's default, or any other behaviour.
- Deploying (separate step: dev -> tst -> main).

## Promotion check

One line of config, one subsystem, no schema, no new service: stays a Task.
